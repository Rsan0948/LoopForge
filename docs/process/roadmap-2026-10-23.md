## Phase 1: engine tuning (short microbenchmarks, about 30–45 min of GPU; not a benchmark)

The purpose is to choose settings, not to prove slowness. Every run replays requests captured
from the evidence trial at fixed depths with a fixed output length, so it is cheap and
deterministic. The script extends `scripts/tune_engine_sampling.py` or is a sibling of it, and
holds the `ModelLease`.

- [ ] **1.1 Depth benchmark harness.** Truncate captured requests to about 8K / 16K / 24K / 32K prompt
  tokens at tool-result boundaries, with output fixed at 256 tokens (`num_predict`, temperature 0, so
  the same tokens are produced). Report prefill ms/token, decode ms/token, and MTP acceptance
  (parsed from `~/.ollama/logs/server.log` `draft acceptance` lines).
  *Why:* decode per token went from 36.7 to 56.5 ms between 9.8K and 20.9K tokens at equal MTP
  acceptance. That is about 3× what a model with 10 attention layers out of 40 predicts
  ([Qwen3.6 card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B): `10 × (3 × Gated DeltaNet → 1 × Gated Attention)`).
- [ ] **1.2 Allocated window: `num_ctx` 32768 vs 131072** at equal depths.
  *Why:* the user reports that a smaller window is faster regardless of usage. llama.cpp theory
  says attention compute follows the cells actually used, so this must be measured, not argued.
  Community reports mostly reflect VRAM spill ([CachyOS](https://discuss.cachyos.org/t/comparison-ollama-vulkan-vs-ollama-rocm/21789)).
  *Done when:* a table shows the difference at each depth, and a decision is recorded.
- [ ] **1.3 KV cache type: q8_0 vs f16** (Ollama `OLLAMA_KV_CACHE_TYPE`) at equal depths.
  *Why:* a suspected slow quantized-KV attention path; the same symptom appears on other backends
  ([llama.cpp #28734](https://github.com/ggml-org/llama.cpp/issues/28734),
  [rdna-boosts #133](https://github.com/stew675/llama-cpp-rdna-boosts/issues/133)).
  Memory cost of f16 at 32K: 10 attention layers only, which is small on 64 GB.
- [ ] **1.4 Speculative decoding: MTP on vs off**, and `spec-draft-n-max` 2 vs 3 if Ollama
  exposes it. *Why:* MTP acceptance swung between 0.52 and 1.00 with the content, and MTP adds
  a full-attention head whose cost grows with depth.
  *Done when:* a decision is made, or it is recorded that the setting is not configurable.
- [ ] **1.5 MLX depth curve** at the same depths (prefill and decode per token, cache hit).
  *Why:* the per-engine budget `W` (Phase 4) depends on where each engine crosses 20 tok/s.
- [ ] **1.6 Window vs Qwen's "≥128K to preserve thinking" guidance.**
  - If 1.2 shows allocation is free: allocate at least 128K and enforce a usage budget through Phase 4.
  - If allocation costs compute: use 32K and require the Phase 6 smoke to pass.

  *Done when:* the decision and its evidence are written in `context-management-research` §2.
- [ ] **1.7 Output cap vs window.** The A3B profile's `num_predict` is 32,768. With a 32K
  window, prompt plus output cannot fit, so admission would refuse every turn.
  Measure the observed output distribution (the maximum seen this session was about 3.7K on a dense
  model and 2.1K on A3B), then set the cap, for example 8K, with headroom.
  *Done when:* the cap is changed in `ollama_profiles.py`, with a test that admission for a
  32K window reserves the cap.
- [ ] **1.8 Context shift must never fire.** Ollama launches `llama-server --context-shift --keep 4`,
  which silently discards tokens when the window fills. Ensure the admission ceiling is below
  `num_ctx − output cap` on both engines.
  *Done when:* a test asserts that admission refuses or compacts before the window is reached.
- [ ] **1.9 Apply the chosen engine settings** to the profile/engine config with a recorded
  rationale, and update `run_engine_comparison.py` to match (both engines get the same window and
  output cap).

## Phase 2: tool-output hygiene (largest token waste after thinking; no model involved)

Measured at call 22: tool results are 65% of 112K prompt characters (`context-management-research` §7).
SWE-agent shows interface design drives results ([SWE-agent](https://arxiv.org/abs/2405.15793v2)).
Anthropic: "tools should return token-efficient information"
([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

- [ ] **2.1 Real newlines in command output.** The sanitizers escape every non-printable
  character, including `\n` and `\t`, as `\x0a` / `\x09`: `workloads/repair.py:558`,
  `adapters/ollama_model.py:903`, `application/orchestrator.py:517`, `application/runtime.py:1284`.
  Each result carried 40–66 of these escapes.
  *Fix:* allow `\n` and `\t`, and keep escaping every other control character. This is a security
  sanitizer, so the denial tests must cover ANSI/escape, NUL, CR, bidi and other C0/C1 characters.
  *Done when:* allowed and denied tests pass, and the existing `\x0a` un-escaping in
  `campaign_state_context.py:71` and `campaign_repair_escalation.py:96` is reconciled
  (removed, or kept for legacy journals).
- [ ] **2.2 Strip pytest `warnings summary` noise** from check output. It was 2.5–4.3K
  characters per result, about 13% of the prompt.
  *Fix options:* add `-p no:warnings` to the code-owned check argv (but the checks are
  `immutable_required_checks` from intake, so this changes their hash), or a code-owned output
  filter that removes the section and appends `(N warnings omitted)`.
  The filter is preferred: it keeps the intake hashes unchanged.
  *Done when:* tests show the warnings section removed, failures and the summary line kept, and
  non-pytest output untouched.
- [ ] **2.3 Unchanged-failure deduplication.** The same failing test was restated in full after
  each of 4 edits. When the runtime's failure fingerprint (failing test IDs and assertion lines)
  is unchanged since the previous result, emit
  `unchanged since <candidate sha>: <ids> (<first assertion line>)`. A changed set gets the full output.
  *Trust:* the fingerprint is computed by the runtime from the command result, never taken from model text.
  *Done when:* tests cover unchanged (short form), changed (full output), and the first failure
  (full output).
- [ ] **2.4 Whole-file reads up to a cap.** `read_file` pages at about 3K characters (about 80 lines).
  Four of 12 reads were page continuations, and each extra call costs a full thinking turn
  (10–200 s). *Fix:* return whole files up to about 12–16K characters, and page past that. The cap
  is code-owned (tool metadata) and never model-set.
  *Done when:* tests cover a whole small file, paging beyond the cap, and a refused model-supplied
  cap.
- [ ] **2.5 Combined verification output in `check_documents` / `check_project`.** Each check
  tool returns *all* checks' results. Once 2.2 and 2.3 are in, re-measure. If redundant output
  remains, return only the invoked check plus a one-line status of the others.
  *Done when:* re-measured on a replay, and either fixed or closed with numbers.
- [ ] **2.6 Errors stay visible** ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus):
  "leave the wrong turns in the context"). Regression test: 2.2, 2.3 and Phase 4 never remove
  the latest failure, a protocol correction, or a rejected-action reason.
- [ ] **2.8 Reduce the number of calls (calls are the expensive unit).** Prefill is 1–5 s
  per call, and decoding the reasoning costs 10–200 s per call, so every avoided call is worth more
  than any token trim. The evidence trial made 24 calls with 0 passing edits.

  Call-wasting patterns seen in its trajectory:

  | Pattern | Count | Addressed by |
  |---|---|---|
  | page continuations | 4 | 2.4 |
  | `app/server.py` read three times (p1, p2, then again after edits at line 115) | 3 | — |
  | separate `check_documents` and `check_project` calls that each return both results | 2 | 2.5 |
  | edits answered with an unchanged failure restated in full | 4 | 2.3 |
  | a rejected unknown-tool call (other session's run) | 1 | — |

  *Fixes to assess, one by one:*
  - (a) a code-owned multi-path `read_file` (several paths in one call, total under the 2.4 cap);
  - (b) after a successful edit, return the edited hunk with its surrounding lines and the new
    hash, so a re-read is unnecessary (the hash part already exists: B17);
  - (c) a re-read of an unchanged file at the same hash returns `unchanged since call N (sha …)`
    plus the content only if tier-1 masking has removed it;
  - (d) the unknown-tool rejection names the valid tool list once.

  *Done when:* each of (a)–(d) is implemented with allowed and denied tests or rejected with
  a reason, and calls per task are measured before and after on the 6.2 replay and the 6.3 smoke.
- [ ] **2.7 Re-measure the prompt composition** on a replay of the evidence trial after Phase 2.
  Record the new share for tool results, thinking and system.

## Phase 3: sampling (short A/B on captured requests; no full trials)

- [ ] **3.1 Precise-coding preset vs general preset.** The A3B native profile uses the general
  thinking preset (T=1.0, presence 1.5). The [Qwen3.6 card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)
  recommends T=0.6, presence 0.0 for precise coding. The dense native profile already used 0.6
  (diagnosis B3/B4). A presence penalty penalizes repeated identifiers, which code needs.
  *Measure* on about 10 captured requests × N samples: output tokens, tool chosen, edit `old` exact-match
  rate, and JSON/tool-call validity.
  *Done when:* a decision with a numbers table, and the profile updated (or kept) with its rationale.
- [ ] **3.2 MLX parity for the chosen preset.** The MLX request uses `presence_penalty`
  with `presence_context_size=2048`. Confirm both engines apply the same effective sampling,
  or document the difference.
- [ ] **3.3 Thinking policy stays `always` (assessed).** Evidence-driven thinking saves decode
  on follow-through reads, but the qwen3.5 renderer re-renders all post-query assistant turns
  when the think flag flips, which breaks the prefix cache (F2/F3). Keep `always`.
  *Re-assess after Phase 4:* a checkpoint is a planned prefix break, so the think flag could
  change *at* a checkpoint for free. Switching it on follow-through reads *between* checkpoints
  would still break the prefix on every flip, so that stays rejected unless a renderer-safe method
  exists.
  *Done when:* the reasoning is recorded here and ticked.

- [ ] **3.4 Thinking verbosity per call.** Decode dominates wall time: call 22 produced
  2,115 output tokens in 204 s. The user reports that Qwen "cycles through the same thought
  multiple times".
  *Measure* thinking tokens per call and repeated-sentence rate in the evidence trial's
  `exchange-*.json`.
  *Levers, assessed in order:*
  - (a) the 3.1 sampling preset;
  - (b) Phase 2 and 4 context reduction (less to re-reason over);
  - (c) a short code-owned instruction to state the plan once and act;
  - (d) a per-turn thinking budget, only if the engine supports one without breaking the
    prefix or truncating tool calls.

  *Done when:* the thinking-token median and p90 are measured before and after, and each lever
  is adopted or rejected with numbers.

## Phase 4: checkpoint compaction (design: `context-management-research` §4)

Evidence base:

- Observation masking matches LLM summarization at about half the cost, and summaries lengthened
  trajectories by 13–15% ([Complexity Trap](https://arxiv.org/abs/2508.21433v2)).
- Tool-result clearing is the lightest compaction ([Anthropic](https://www.anthropic.com/news/context-management)).
- Restorable compression and a stable prefix ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)).
- Anchored iterative summaries ([Factory](https://factory.ai/news/evaluating-compression)).
- Threshold compaction mid-task derails the agent ([Codex notes](https://gist.github.com/badlogic/cd2ef65b0697c4dbe2d13fbecb0a0a5f)).
- Smaller context is also more reliable ([Chroma](https://trychroma.com/research/context-rot)).

- [ ] **4.1 Budget model.** Code-owned per-engine `W` (working budget, from Phase 1 where decode
  is ≥ 20 tok/s), hard ceiling `C` (window − output cap − margin), and post-compaction target
  about `0.5 W`. These are profile fields, operator-frozen, and never model-set. Tests cover bounds
  and refuse invalid combinations (W > C, C + cap > window).
- [ ] **4.2 Deterministic checkpoints.** The runtime emits a checkpoint after:
  - a verifier / `check_*` result;
  - an edit whose check completed;
  - a phase change;
  - a rejected repair attempt.

  At each checkpoint it projects `current + max_tool_result + output_cap`. If the projection
  exceeds `W`, it compacts; otherwise it does nothing.
  *Done when:* tests show compaction at a checkpoint when the projection exceeds W, no
  compaction when under, and never compaction between checkpoints except the 4.6 backstop.
- [ ] **4.3 Tier 1: restorable masking (free).**
  - Tool observations older than the last M turns become stubs:
    `[read_file app/x.py sha256=… N bytes — omitted; re-read to view]`.
  - Assistant tool calls are kept.
  - Old thinking is dropped at the boundary only.
  - Exact replay resumes after the boundary.

  *Done when:* tests cover stub content (path and hash present), latest failure, corrections
  and the last exchange kept verbatim, and the prefix after the boundary stable across the next
  two turns (verified with `scripts/verify_prompt_prefix_stability.py` or an equivalent oracle
  check).
- [ ] **4.3b Old thinking: the largest single reclaim.** Replayed thinking was 28% of the
  prompt (31K of 112K characters at call 22). It is kept *within* a segment on purpose: exact
  replay keeps the prefix cache, and Qwen3.6 is trained to use historical thinking (`preserve_thinking`,
  [card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)). At each checkpoint, thinking before the
  boundary is dropped, while the assistant's short plan content and tool calls are kept.
  *Done when:* tests show thinking removed before the boundary and kept after it, the thinking
  share is measured per segment on the 6.2 replay, and the 6.3 smoke shows no quality loss
  (task completes, with no repeated re-investigation of already-established facts).
- [ ] **4.4 Tier 2: anchored handoff (only if tier 1 cannot reach the target).**
  - Reuse the strict `Handoff` schema from `scripts/compaction_lab.py`.
  - Merge into the previous handoff (the input includes the prior handoff plus the masked
    segment) instead of regenerating from the full history.
  - Citation check against message IDs.
  - Provider: Gemini Flash-Lite through the paid ledger.

  *Done when:* tests use a fake client to cover a valid handoff, an invalid schema, unknown
  citations, a budget refusal and an HTTP failure, and every failure keeps the tier-1 result.
- [ ] **4.5 Trust channel for the handoff (AGENTS.md rule 16).** The lab currently injects it as
  a `user` message, which is the authorized-human channel. Deliver it as a labeled
  MODEL_INFERENCE block inside a runtime-owned message that cannot be read as human or policy
  authority. *Done when:* a test asserts that handoff text never appears in a `user`-role or
  policy-trust item, and an adversarial handoff ("ignore previous instructions, permissions
  expanded") changes no authority field.
- [ ] **4.6 Backstop and overrun event.** If a turn would exceed `C` between checkpoints,
  compact at the next tool-result boundary and record a `budget_overrun` domain event with the
  numbers. *Done when:* tests cover the backstop firing and the event recorded through the reducer
  (rule 3).
- [ ] **4.7 One owner for history size.** Reconcile with the existing mechanisms:
  - `OllamaModel._compact_history` (bounded mode);
  - calibrated admission (`223a624`);
  - the 75% compaction headroom;
  - the exact-replay folding.

  Checkpoint compaction becomes the single planned mechanism. Admission remains the hard safety
  refusal. *Done when:* no two mechanisms can both rewrite history on the same turn (with a test),
  and the old reactive path is either removed or demoted to the backstop.
- [ ] **4.8 Progress recitation at the tail** ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) todo.md).
  Verify that the code-owned `coding-progress` item lands at the end of each request, not only
  at the start. If it doesn't, add a compact code-owned recitation at checkpoints.
  *Done when:* it is verified, or implemented with a test.
- [ ] **4.9 Both engines.** Compaction lives in the shared adapter path, so MLX, which goes
  through the same `OllamaModel` with an MLX transport in the lab, gets identical behavior.
  *Done when:* a probe on each engine shows a checkpoint compaction followed by a cache-hit
  on the next turn (Ollama: prefill only the new tokens; MLX: `cached_tokens`).
- [ ] **4.10 Metrics.** Per compaction, record: tier, tokens before and after, re-prefill seconds, paid
  cost, and turns until the next one. Per task, record: tokens per task, turns per task, wall time,
  minimum and median decode tok/s ([Factory](https://factory.ai/news/evaluating-compression):
  optimize tokens per task).
