# Bounded frontier repair escalation

The operator authorized a trial of independent Gemini repair help after the local
model demonstrates repeated failure. The feature is opt-in through frozen
`CampaignConfig.repair_escalation`, supported only by `qwen-state-v1`. Prepared
goals also require explicit remote-data authority. Disabled serialization preserves
the canonical hashes of old intakes; editing an existing intake to enable help is
denied by its frozen worker binding. Terminal goals are never reactivated.

## Trigger and handoff

The wrapper projects failed verification events and their following measured
candidate snapshots. Three consecutive failures of the same normalized diagnostic,
or two with that failure and an identical patch, trigger a specialist turn. Timing
noise and check-receipt metadata do not create a new failure identity; expected and
actual business values remain significant. Ordinary reads are not repair attempts.

The independent stateless Gemini role receives a bounded packet of current scoped
source and hashes, exact diagnostic evidence with explicit omission counts, recent
action arguments, the objective and fixed check names. It receives no orchestrator
conversation. This provides independent ready roles, not a guarantee of provider
compute residency or instant inference. The specialist uses a separate HTTP client
with a 180-second timeout and no automatic provider retries.

A strict diagnosis schema returns evidence, next steps, verification and an optional
exact patch. A direct patch must change at most two physical lines in one permitted
file, fit a 2,000-byte old/new allowance, match supplied source and its full-file
hash, and still match the candidate fingerprint after inference. The actual final
file diff is checked as well as the snippet. It becomes an ordinary `apply_edits`
proposal: existing metadata, permission, scope, protected-file, atomic-write and
verification controls remain authoritative. All fixed checks and a fresh independent
review remain required. Failed or stale proposals do not bypass these controls.

Larger fixes become durable `MODEL_INFERENCE` guidance in the next fresh context.
The local model makes the implementation. Non-executable patch bodies stay in the
ledger rather than crowding the state packet; optional old source excerpts may be
omitted whole to make space. Guidance cannot become policy or authorized-human
instructions. The pure acknowledgement action has code-owned read permission,
internal sensitivity, a five-second timeout and no retries.

## Bounds and recovery

An append-only SQLite repair ledger uses the pure domain reservation/settlement
reducer. It permits one intervention per failure identity, at most three overall,
and a frozen ceiling of at most $0.50 across coding attempts. Reservations are
durable before HTTP; interrupted unknown outcomes retain their maximum charge and
cannot silently replay. Valid usage settles the reservation; unknown usage charges
the bound. Returned usage also debits the runtime's token and dollar budget. Calls
are denied when their maximum token/cost reserve or 180-second time allowance will
not fit. Provider/schema failures return bounded diagnostic state and let the local
model continue within its existing controls.

This opt-in goal-worker path returns without joining the worker thread. The
coordinator can poll durable state and controls during repair inference; unchanged
polls neither call Gemini nor append duplicate goal events. Keyed reconciliation
does not dispatch another worker. Existing profiles retain their blocking behavior.

## Read-loop recovery

The first specialist-enabled trial reached lint success but stopped at
`CODING_NO_NEW_EVIDENCE` after repeated source reads. No specialist call occurred:
the original trigger counted repeated failed checks, while this failure involved
repeated reads between checks. Two unchanged retries were correctly rejected by
`CODING_STALLED_RETRY`. The goal is terminal and remains blocked.

Fresh escalation and the eight-turn stop guard now share the same durable event
projection. Six turns without a changed candidate or new source evidence trigger
help before stopping. A newly journaled specialist diagnosis counts as new evidence
and gives the local model a bounded continuation window. Repeating an acknowledgement
or rereading identical advice does not reset that window. Original permissions,
timeouts, hard budgets, check circuits and terminal-state rules remain in force.

Before stall help, a synthetic proposal reproduces the failure using an existing
registered fixed check. It selects the failed project check rather than assuming
the first listed check is relevant. Full output is archived by content hash outside
the candidate; bounded exact head/error-line/tail excerpts retain root errors that
would otherwise disappear in a long traceback. Specialist packet admission omits
whole optional source files to stay within the request bound.

The fresh successor `.loopforge/tasks/reconciliation-stall-recovery/` imports the
original terminal run `run_2eabf99aba21` as historical domain events. Its frozen
`repair_recovery_run_id` permits immediate recovery only when those events prove
an eight-turn no-evidence failure and the current candidate fingerprint matches.
Missing proof, a different terminal reason or a changed candidate do not grant an
immediate intervention. The imported run never becomes active. Linked failed runs
within an existing task can provide the same bounded evidence; intervention
deduplication and budgets survive retries.
