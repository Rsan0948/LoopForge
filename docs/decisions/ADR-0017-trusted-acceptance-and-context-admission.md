# ADR-0017: Trusted acceptance receipts and explicit context admission

Date: 2026-10-20
Status: implemented for Phase 1; prepared Python acceptance probes qualified

## Context

A passing editable project test does not independently establish the requested
behavior. A receipt for a different patch, task contract or run cannot authorize
acceptance. Provider usage tokens and the serialized request's byte size also
serve different purposes; calling the byte limit a measured tokenizer count
obscures context pressure and compaction.

## Decision

`CodingTaskConfig.acceptance_probes` holds operator-frozen Python probes with
explicit criterion identities and descriptions. Their source lives in the task
contract, outside editable repository files. Commands are generated by code and
run through the existing immutable-image container capability contract. Probes
cannot be reused from cached command results. They supplement project checks.

A successful command must reach the generated completion marker after its probe
body finishes. Exit code zero alone cannot pass an incomplete probe. This
protocol detects early termination; it is not proof against arbitrary malicious
programs that deliberately counterfeit grader output. Behavioral assertions,
scoped edits and fresh review remain necessary.

`RepairVerifier` returns typed `CheckOutcome` evidence. The coding verifier binds
acceptance criteria to the base revision, exact patch bytes/modes, a versioned
hash of the frozen task contract, and the actual verification run. Candidate or
contract changes during checks invalidate the result. Missing, failed or
unexecuted criteria cannot be replaced by success prose.

Coding and fresh-review receipts are persisted in the append-only coding event
details. Starting review validates the coding receipt. Local acceptance validates
the fresh-review receipt against the current candidate and contract and requires
its run to have succeeded. This does not merge, push or deploy changes.

Existing persisted tasks default to no independent probes and retain their
previous checks-only meaning. They are not silently reinterpreted or rerun.
New supervisor compositions must require configured acceptance criteria before
claiming independent acceptance. Initial probes support Python; no general
language support or semantic-correctness guarantee is implied.

`ContextAdmission` records the measurement basis, complete serialized request byte
count, input token bound, context/output/framing reservations and compaction
count. Ollama's fallback is explicitly a UTF-8 byte upper-bound estimate, with
an injectable code-owned token counter. It is not an exact tokenizer. The default
output reservation is now also an actual `num_predict` limit.

Successful model turns and failed attempts persist these optional diagnostics.
Historical events without them retain their meaning. Compaction preserves the
current runtime-policy and authorized-human items with their original trust
labels, even when their item names are unfamiliar. Oversized preserved content
fails admission before the provider call. The console exposes the measurement
basis; provider-reported usage remains separate.

A scripted counterfactual does not measure a live provider request, so admission
diagnostics are excluded from behavioral comparison. Admission failures and all
actual action/control outcomes remain part of that comparison.

## Verification

The container qualification uses an intentionally misleading green project test,
a wrong patch, an early-exit patch and a correct patch. Only the correct patch
reaches fresh review and a local commit in the isolated fixture checkout.
Restarted composition recovers durable receipts; a subsequent candidate edit is
denied acceptance. The original fixture checkout remains unchanged.

Offline regressions cover identity mismatches, missing/contradictory typed
outcomes, strict receipt decoding, mutated contracts, edits during verification,
explicit token/byte measurements, output-reservation denial before HTTP,
compaction of human constraints and counterfactual comparison.
